# APB_PROTOCOL_VERIFICATION
# APB Master Verification

SystemVerilog class-based (non-UVM) testbench for functional verification of an
AMBA APB Master (`apb_master`), simulated on Questa/ModelSim 10.6c.

## 2. Design Under Test (DUT)

`apb_master` is a 3-state Moore FSM (`IDLE → SETUP → ACCESS`) that converts a simple
user-side request (`transfer`, `write_read`, `addr_in`, `wdata_in`, `strb_in`) into an
AMBA APB master transaction (`PSEL`, `PENABLE`, `PWRITE`, `PADDR`, `PWDATA`, `PSTRB`)
and returns `rdata_out`, `transfer_done`, `error` to the user side once the slave
asserts `PREADY`.

```
Parameters : ADDR_WIDTH = 4, DATA_WIDTH = 32   (see defines.svh)
```

## 3. Testbench Architecture

```
generator --(mbx_gen2drv)--> driver --(bridge_interface)--> DUT (apb_master)
                                 |                              |
                          (mbx_drv2scr)                 (mon_interface)
                                 |                              |
                                 v                              v
                            scoreboard <--(mbx_mon2scr)--- monitor
                                 |
                          PASS/FAIL report

apb_assertions is bound directly to the DUT and runs independently
of the mailbox-based data flow above.
```

* **generator** — randomizes `drv_transaction` (operation, address range, strobe pattern), `TX_COUNT = 10` per run.
* **driver** — drives the transaction pin-level onto `bridge_interface` (`cb2drv` clocking block); samples a functional covergroup (`write_read × addr_in` cross, `strb_in`).
* **monitor** — behaves as an ideal APB slave (`IDEAL_TEST`), generates `PREADY` / `PSLVERR` / `PRDATA`, and samples the bus into `mon_transaction`.
* **scoreboard** — `reference_model()` / `data_match()` compare the driver's expected transaction against the monitor's observed transaction; maintains `PASS` / `FAIL` counters and prints the final report.
* **apb_assertions** — 6 SVA properties checking reset behavior, SETUP→ACCESS sequencing, signal stability during ACCESS, `transfer_done` timing, and PSEL re-assertion after `PREADY`.

## 5. How to Run

```bash
# Compile + elaborate + run with coverage, from the project directory
vsim -vopt work.test_bench \
     -voptargs="+acc=npr" \
     -assertdebug \
     -l log_file.log \
     -coverage \
     -c -do "coverage save -onexit -assert -directive -cvg -codeAll ucdb_file.ucdb; run -all; exit"

# Generate the HTML coverage report from the UCDB
vcover report -html ucdb_file.ucdb -htmldir covReport -details
```

Console output (`log_file.log`) prints, in order: GEN/DRV/MON transaction traces,
per-transaction SCOREBOARD PASS/FAIL, the final `SIMUALTION REPORT` (PASS/FAIL
counts, pass %), and the final `ASSERTION REPORT` (which of the 6 assertions failed).
